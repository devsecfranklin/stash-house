\section{Storage Infrastructure}

\subsection{Active Disk Topology (chonk -- August 2026)}

All compiled documents and web artifacts target wonderland; chonk serves as local scratch space. Physical topology on chok:

\begin{itemize}
    \item \textbf{/mnt/backup1}: Source directory for Ansible repos, workspace code, and build artifacts
    
    \item \textbf{/mnt/clusterfs}: Scratch disk for temporary compilation, LaTeX builds, and intermediate files
    
    \item \textbf{/mnt/snowy}: Bulk storage -- formerly a full NFS share; hard disk physically removed, now mounted as raw drive only
\end{itemize}

The following mount points have been purged:
\begin{itemize}
    \item \textbf{/mnt/storage1}: Completely removed across all roles and /etc/exports on all hosts
    \item Legacy /mnt/storage2, /mnt/storage3: Purged from inventory references
\end{itemize}

\subsection{NFS Mounts -- Current State}

The lab relies on NFS for shared storage. Active mounts as of August 2026:

\begin{itemize}
    \item \textbf{stargate:/mnt/clusterfs2}: Primary cluster workspace; mounted on stargate and accessible from wonderland via SSH-sync pipelines
    
    \item \textbf{Jetson home directories}: Shared from stargate via \texttt{stargate:/mnt/clusterfs2} -- provides consistent \textasciitilde/home for node900--node903
\end{itemize}

\subsection{StrictModes and Permission Requirements}

OpenSSH StrictModes enforces strict permission checks on home directories. Required permissions:

\begin{itemize}
    \item Home directory: \texttt{0750} (rwxr-x---)
    
    \item \texttt{\textasciitilde/.ssh}: \texttt{0700} (rwx------)
    
    \item \texttt{\textasciitilde/.ssh/authorized\_keys}: \texttt{0600} (rw-------)
\end{itemize}

All Jetson nodes must comply with these permissions or SSH authentication fails silently. NFS-mounted homes require uid/gid consistency between stargate and each Jetson host.

\subsection{Snapshot and Backup Strategy}

The lab uses bare git repos for version control and backup:
\begin{itemize}
    \item GPG-encrypted repositories synced across hosts for credential protection (Stash House project)
    \item Pass-based password store with GPG backend
    \item No LFS -- ABSOLUTE RULE: do not use git-lfs anywhere. Microsoft once held Minecraft chunk files hostage when a repo hit the 10GB GitHub limit with LFS enabled.
\end{itemize}

\subsection{LFS Policy Reminder}

\textbf{ABSOLUTE RULE: Do NOT use git-lfs anywhere in any lab-franklin repository.}

This applies across all repos: training-ai, minecraft, Ansible collections, everything. The incident with Minecraft chunk files being held hostage by GitHub when the repo hit 10GB with LFS is a real precedent -- never risk it.
