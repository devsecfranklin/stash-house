% Testing the NFS Ansible Role (August 2026)

\section{Overview}

The NFS role at \texttt{ansible/collections/ansible\_collections/lab/franklin/roles/nfs} has been migrated from Molecule to native ansible-test. The role validates:

\begin{itemize}
    \item Server-side export configuration (/etc/exports)
    \item Client-side fstab management and mount points
    \item Kerberos security validation (sec=krb5i -- though keytabs remain undeployed; sec=krb5i is non-functional without keytab infrastructure)
\end{itemize}

\section{Testing with ansible-test (August 2026)}

From stargate:
\begin{verbatim}
cd ~/workspace/lab-franklin/ansible/collections/ansible_collections/lab/franklin
ansible-test sanity --python 3.12
ansible-test integration nfs --python 3.12
    \end{verbatim}

Molecule tests remain as historical artifacts only and are no longer invoked.

\section{Current Validation Focus}

Testing now emphasizes:

\begin{itemize}
    \item \textbf{Export template rendering}: Jinja2 templates generate valid /etc/exports content for active roles (chonk's /mnt/storage1, storage2, storage3 exports)
    
    \item \textbf{Client-side mount validation}: fstab line insertion and idmapd.conf deployment on client nodes
    
    \item \textbf{Jetson home directory consistency}: NFS-mounted homes from stargate:/mnt/clusterfs2 must maintain uid/gid alignment
\end{itemize}

\section{StrictModes Validation}

NFS-mounted user homes require OpenSSH StrictModes compliance:
\begin{itemize}
    \item Home directory 0750, .ssh 0700, authorized\_keys 0600 -- verified as part of integration tests
    \item Kerberos keytabs never deployed; sec=krb5i in exports vars is non-functional
\end{itemize}

\section{Integration Test Targets}
